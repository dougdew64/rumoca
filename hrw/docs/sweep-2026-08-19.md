## Finding 1 — Absence tags whose targets are prose, not symbols

**Severity: real, and one instance is already false.**

`CLAUDE.md`'s claims-of-absence rule requires a tag naming *the symbol as it will actually be
spelled*, because `doc_citations::claims_of_absence_are_still_true` fails only when the target
**resolves**. Its own warning: *"a misspelled target is silently permanent"* — a tag that resolves
nothing is indistinguishable from a claim that is still true.

**Two tags name prose rather than a symbol, so they can never fire:**

| tag | where | status |
|---|---|---|
| `<!-- unbuilt: hrw tour-stop link form -->` | `docs/ideas.md:3629` | **FALSE — the feature shipped 2026-08-17** |
| `<!-- unbuilt: hrw unsafe_code lint -->` | `docs/tech-debt.md:1034` | unverified; needs checking against `[workspace.lints]` |

The first claims *"a link form that opens a fixture tour at a named stop"* is not built.
**`hrw://tour/<name>/stop/<slug>` was built on 2026-08-17** and now lands precisely. The document
has been telling a reader the opposite for two days, and **the checker designed to catch exactly
this could not**, because the target is a phrase.

**Why this is the sweep's most valuable finding:** it is a *class*, not an instance. The mechanism
that was supposed to protect against stale absence claims has a hole that is invisible from
inside — a green checker over unverifiable tags looks identical to a green checker over verified
ones.

**Proposed fix:** make the checker fail on a tag whose target is *not symbol-shaped* — no spaces,
or matching a known form like `hrw://…`. That converts "silently permanent" into "fails at the
moment it is written", which is the only time the author knows what they meant.
