# HarmonicOscillator — why this specimen exists

**Intent, not explanation.** *How* this specimen behaves is regenerated on demand from
[`trace/`](trace/) — generated by `cargo run -p hrw --example gen_trace -- HarmonicOscillator`, and
therefore correct by construction. What **cannot** be regenerated is why someone made this file —
the code never says what it is *for*.

## Authored to trigger

Nothing in the compiler. It is authored for the **solver**, and specifically so that solver error
can be *measured* instead of assumed.

`SingleInertia`, the corpus baseline, has the exact solution `phi = t^2/2`, `w = t`. That is a
polynomial, and it makes integrator order invisible: several methods reproduce it to machine
precision, so comparing them teaches nothing. This model's exact solution is `x = cos(omega*t)`,
`v = -omega*sin(omega*t)` — transcendental, so **every** method has a truncation error, and a
first-order method and a fourth-order one separate by a measurable amount that shrinks at
different rates as the step shrinks.

It is also the smallest model with an **oscillatory** trajectory, as against the monotone ones in
the rest of the corpus, which is the shape stability regions are drawn for.

## Measured against truth, 2026-09-24

Rumoca 0.9.20, default settings, `t_end = 2`:

| quantity | Rumoca | `cos`/`sin` | error |
|---|---|---|---|
| `x(1)` | 0.540301464 | 0.540302305868 | −8.4e−7 |
| `v(1)` | −0.841470198 | −0.841470984808 | +7.9e−7 |
| `x(2)` | −0.416145883 | −0.416146836547 | +9.5e−7 |
| `v(2)` | −0.909291938 | −0.909297426826 | +5.5e−6 |

The error is small and does not grow by orders of magnitude across the run — consistent with a
tolerance-controlled solver rather than with accumulation. **That table is the point of the
specimen**: it is a number a reader can check, not a claim to be believed.
