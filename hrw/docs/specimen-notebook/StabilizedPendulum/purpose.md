# StabilizedPendulum — why this specimen exists

**Intent, not explanation.** *How* this specimen behaves is regenerated on demand from
[`trace/`](trace/) — generated by `cargo run -p hrw --example gen_trace -- StabilizedPendulum`, and
therefore correct by construction. What **cannot** be regenerated is why someone made this file —
the code never says what it is *for*.

## Authored to trigger

**The pendulum's index problem solved by the modeller instead of by the compiler.**

`CartesianPendulum` is index 3: the constraint `x^2 + y^2 = L^2` contains no derivative, so
nothing in the system determines `lambda` until the constraint is differentiated twice. On 0.9.20
Rumoca had no route through that, so it stopped there (v0.10.4 has one — below). This file is the
*other* way out, and
it is the way the field used before there was an algorithm: differentiate the constraint by hand,
and add feedback terms so the differentiated form does not drift away from the original one —

```
C = x^2 + y^2 - L^2,    Cdd + 2*alpha*Cd + beta^2*C = 0
```

published by Baumgarte in 1972, sixteen years before Pantelides. The resulting model is index 1
in the portable Modelica subset, with no compiler feature required.

It exists so the ladder has a rung between "index 3 is a wall" and "the compiler removes the
wall": **the wall was first climbed by hand**, and a reader can write that model themselves.

## What it found, 2026-09-24 — two walls, not one

Measured on Rumoca 0.9.20, and this was not the expected result:

```
Dae              Ok        4 state(s), 1 algebraic(s), 5 continuous equation(s)
Structural       Ok
IndexReduction   Ok        already index-1 — the reduction funnel is a no-op here
Initialization   Flagged   IC planning failed: structurally singular system: 0 matched
                           out of 1 equations and 1 unknowns; unmatched unknowns: lambda
Events           Ok
SolveLowering    Ok
simulation       FAILED    BDF: Failed to factorise matrix: SymbolicSingular { index: 4 }
```

**The hand reduction works.** Where `CartesianPendulum` reports `Structural … singular` and then
`still singular after reduction`, this model passes both — and Rumoca correctly identifies
it as already index 1. That is a real confirmation that Baumgarte's 1972 construction does what
it claims, checked by a compiler that has no idea it was applied. **The substance remains true on
v0.10.4**, and it is the durable half of this specimen's value: Structural is not singular, and
the reducer needs **no reduction round**. Its outcome is `sorted` rather than `borrowed`, though —
derivative-alias normalization rebuilds the system first, so the Index reduction note reads
*normalized without a reduction round*, not *already index-1*.

**And on 0.9.20 it still did not run.** Initialization could not match `lambda` to an equation, so
`lambda` never received a consistent initial value, and the solver's iteration matrix was singular
at index 4 — which is `lambda`, the fifth variable.

### ⟶ IT RUNS ON v0.10.4 — measured 2026-11-04, and the comparison is now the point

**Both walls are down.** Initialization produces its plan, solve lowering produces a problem, and
the model simulates 501 samples to t = 2 s on **4 states**, with `lambda` peaking at **29.4300**
(29.4301 on v0.10.4)
against the hand-computed rod tension 3*mg* = 29.43.

**And `CartesianPendulum` runs too**, which this file was written assuming would not happen: v0.10.4
reduces the *unstabilized* model to **2** states. Its reducer still refuses; state selection then
takes the route Rumoca names *singular system recovered via formal derivatives* — it differentiates
the system formally and selects an independent basis, `$state_coordinates[1..2]` in the run. It
starts as `{y, der(y)}` and **is re-chosen as the pendulum swings**, switching to `x` where a chart
on `y` fails (see `CartesianPendulum`'s purpose, corrected 2026-11-28). Everything else is an
algebraic reconstructed each step from the current chart, not integrated. So the corpus holds the
same physics solved two ways, and the numbers separate them cleanly:

| | this model — Baumgarte, by hand | `CartesianPendulum` — formal-derivative basis |
|---|---|---|
| integrated states | 4 | **2** |
| `\|x² + y² − L²\|`, final sample | 1.3e-06 | **round-off** (`0.0`) |
| `lambda` peak | 29.4300 | 29.4301 |

*(Re-measured on v0.11.0, 2026-11-28, from each trace's final `x` and `y` and `lambda.max`. On
v0.10.4 the rows read 2.9e-06 / 4.6e-12 and 29.4301 / 29.4303.)*

**Many orders of magnitude, and both get the physics right.** Damping a constraint violation keeps
it small; integrating only two independent coordinates and reconstructing the rest leaves the
position constraint nothing to drift on. That is
the clearest statement of what index reduction buys that this corpus can make, and it needs both
specimens to make it — so **this one's purpose has changed rather than expired**: it was evidence
of a gap, and it is now the control in a comparison.

So on 0.9.20 Rumoca's inability to simulate a constrained pendulum was **not only** the missing
index-reduction route. There was a second, independent stop downstream, in initialization of an
algebraic unknown, reached even when the index problem had already been removed. Naming only the
first would have been wrong, and this specimen is what made the second visible.

## Validated by the oracle first

Because the conclusion above blames Rumoca, the specimen was checked in **Wolfram System
Modeler** before anything was concluded (`WSMSimulate`, `{0, 2}`):

| t | `x` | `y` | `lambda` | `x^2+y^2-1` | `m(vx^2+vy^2-g*y)/L^2` |
|---|---|---|---|---|---|
| 0 | 1 | 0 | 0 | 0 | 0 |
| 0.25 | 0.9536646043 | −0.3008717467 | 8.854655724 | −1.5e−8 | 8.854655449 |
| 0.5 | 0.3910487904 | −0.920369948 | 27.08648745 | −2.4e−9 | 27.08648732 |
| 1.0 | −0.986291749 | −0.1650108656 | 4.856269462 | −2.8e−11 | 4.856269461 |
| 2.0 | 0.7935661992 | −0.6084839254 | 17.90768161 | −5.6e−12 | 17.90768161 |

Two things to read there. `lambda` agrees with the analytic tension `m(v^2 - g*y)/L^2` — the same
identity derived in [`dae-pendulum.md`](../../dae-pendulum.md) — to about 1e−9, so the physics is
the pendulum's and not an artefact of the stabilisation. And the constraint residual is **smaller
at t = 2 than at t = 0.25**, which is the whole purpose of the `alpha` and `beta` terms: an
unstabilised twice-differentiated constraint drifts, and this one is pulled back.

The model is therefore correct and portable. **The Rumoca failure is Rumoca's.**
